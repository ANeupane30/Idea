A practical guide to SQL: SELECT, WHERE and JOIN

SQL is the language you use to talk to a relational database. A relational database stores data in tables, and every table is made of rows and columns. Each row is one record, such as one customer or one order, and each column holds one kind of value, such as a name, a price or a date. A primary key is a column whose value identifies each row, and a foreign key is a column that points at the primary key of a row in another table.

The SELECT statement is how you retrieve data from a table. You write SELECT, then the columns you want, then FROM and the name of the table. Writing SELECT name, city FROM customers returns the name and city columns for every row in the customers table. You can choose columns in any order, rename them with AS, and remove duplicates with SELECT DISTINCT, so that each distinct value appears only once in the output.

Most of the time you do not want every row. Filtering with WHERE keeps only the rows that match a condition. Writing SELECT name FROM customers WHERE city = 'Paris' keeps the rows whose city is Paris. Conditions use comparison operators such as equals, less than and greater than, and you can combine several conditions with the logical operators AND, OR and NOT. A condition like WHERE price > 10 AND stock > 0 keeps only the rows that match both parts.

Rows come back in no particular order unless you ask for one. Sorting with ORDER BY puts the rows in order by one or more columns, ascending by default or descending with DESC. Limiting results with LIMIT caps the output to a fixed number of rows, which is useful when you only want the first few rows, such as the ten most recent orders. Sorting and limiting results together is a common pattern: ORDER BY created_at DESC LIMIT 10.

Real data is spread across related tables. An orders table does not repeat the customer's name on every order; it stores a customer_id that links each order to one row in the customers table. Joining tables lets you combine rows from related tables in a single statement. The keys link tables together: the foreign key in orders matches the primary key in customers, and the join uses that match to pair each order with its customer.

An inner join returns only the rows that have a match in both tables. Writing SELECT orders.id, customers.name FROM orders INNER JOIN customers ON orders.customer_id = customers.id pairs every order with the customer who placed it, and leaves out any order whose customer is missing. Inner joins are the most common joins, and when people say join without a qualifier they usually mean an inner join.

A left join keeps every row from the left table, even when there is no match in the right table. Writing customers LEFT JOIN orders returns every customer, and for customers with no orders the order columns are empty, which SQL shows as NULL. Left joins are how you find rows with no related rows, for example customers who have never placed an order, by joining and then filtering with WHERE orders.id IS NULL.

There are other joins too. A right join is the mirror image of a left join, and a full outer join keeps unmatched rows from both tables. A cross join pairs every row of one table with every row of another. You can also join a table to itself, which is called a self join, to compare rows within the same table, such as employees and the managers they report to.

When you combine rows from related tables, give each table a short alias so the statement stays readable: FROM orders o JOIN customers c ON o.customer_id = c.id. Then refer to columns as o.id and c.name. Aliases matter most when the same column name appears in both tables, because SQL needs to know which table each column comes from.

Putting it together, a single SELECT can choose columns, join related tables, filter rows with WHERE, and sort the output with ORDER BY. Practicing these building blocks on a small sample database is the fastest way to become confident with SQL.
